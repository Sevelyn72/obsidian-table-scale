# Table Scale

Drag the right edge of a Markdown table to change its width without changing text size. Use the bottom edge or bottom-right corner to scale the whole table, including its text and formulas. Each table remembers both preferences in Reading view and Live Preview.

## Features

- Drag the right edge to widen or narrow the table while keeping text and formulas the same size.
- Drag the bottom edge vertically or the bottom-right corner horizontally to scale the table uniformly from 50% to 150%.
- Double-click the right edge to restore natural width, the bottom edge to reset scale, or the corner to reset both.
- Save on pointer release and restore after reopening Obsidian. Reading view and Live Preview share the same record.
- Edit and select cell text normally inside the table.
- Keep separate scales for multiple tables and synchronize the same table across panes.
- Preserve records when files or folders are renamed or moved inside Obsidian.

## Requirements and installation

Requires desktop Obsidian **1.13.7 or later**. Windows is the primary test platform; macOS and Linux need further manual validation. Mobile support is disabled.

For manual installation, build the plugin or use the three installable files from a release:

1. Create `<vault>/.obsidian/plugins/table-scale/`.
2. Copy `main.js`, `manifest.json`, and `styles.css` into that directory.
3. Reload Obsidian, open **Settings → Community plugins**, and enable **Table Scale**.

When updating, keep the existing `data.json` file.

For a development install, `node scripts/install-local.mjs <existing plugin directory>` backs up files before copying the build and project files. It preserves the target's `data.json`, `node_modules` and Git history. Close Obsidian first and reopen it after installation.

## Usage

Open a note containing a normal Markdown table. In Reading view or **Live Preview**, move the pointer to the right outer border. When the pointer becomes a resize arrow, hold the left mouse button and drag horizontally. The table grows or shrinks in width; text size stays unchanged. Release to save.

To change the size of text and formulas together with the table, drag the bottom edge vertically or the bottom-right corner horizontally. Changing width after scaling preserves the chosen scale. The minimum achievable width depends on cell contents; long content can constrain how far the table narrows.

The bottom-right corner retains the original horizontal dragging gesture. The table's internal cell borders continue to belong to the native editor. Use **Refresh table scaling** in the command palette if a rendered table needs to be reconnected.

Keyboard users can focus the right edge and use arrow keys to adjust width in 20-pixel increments, or focus the bottom-right corner for 5% scale increments. **Home** restores natural width on the right edge and resets both preferences on the corner. The command and resize hints follow Obsidian's language: Simplified Chinese for Chinese locales, English otherwise.

Try the [example note](examples/tables.md). Raw source mode displays Markdown text rather than a rendered table and therefore has no resize areas.

## Saved data and privacy

Table layouts are stored locally in `<vault>/.obsidian/plugins/table-scale/data.json`. Records contain vault-relative file paths, hashed table identifiers, scale values and optional unscaled widths. No note contents are copied into this file. Version 1 records from earlier releases are loaded without losing their scales; the first layout change saves version 2 data. Older plugins do not support this new data format.

The plugin does not make network requests, collect telemetry, or access files outside the vault. It does not insert markers or styling into Markdown notes. Each vault keeps its own records; copying a note to a different vault does not transfer its scale automatically.

## Limitations

- Table identity uses the note path, normalized header, and occurrence among tables with the same header. Changing body cells or inserting paragraphs preserves identity. Changing headers, or adding/removing/reordering tables with identical headers, can require resetting their scales.
- Standard Markdown tables are supported. Raw HTML tables, complex nesting, and tables generated by other plugins are outside the current scope.
- Live Preview integration depends on Obsidian's native table markup. Themes, other table plugins, or Obsidian updates can affect it.
- Resizing is a display preference for this plugin; other Markdown applications do not read the saved scale.
- If saved data cannot be read or has an unsupported root format, the plugin preserves it and does not activate scaling for that session. Back up and repair or rename `data.json`, then reload the plugin.

## Development

Use Node.js 24 LTS (minimum 22.13) and npm.

```sh
npm ci
npm run check
npm run dev
```

`npm run check` runs ESLint with zero warnings, regression tests, strict TypeScript checking, the production build, and release metadata validation. `npm run package` also stages the three installable assets and local SHA-256 checksums in `dist/<version>/`.

The release workflow attests the installable assets with GitHub build provenance and attaches only `main.js`, `manifest.json`, and `styles.css` to the draft release. Checksums remain available locally.

CodeMirror and the Obsidian API are provided by Obsidian at runtime and are excluded from the plugin bundle. Development dependencies and local plugin data are excluded from Git.
